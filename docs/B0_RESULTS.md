# GeCo2／SAM2 基線驗證結果

完成日期：2026-10-18。實驗編號：`b0-val-b1-boundary-r1`。

我們已在租用 GPU 上完成 GeCo2 官方 FSC 專用權重的完整驗證集推論，整體計數誤差接近論文參考值，可以用作後續 Plan B 實驗的基準。這輪沒有重新訓練，也尚未證明新增方法有效。

## 測試內容與數量背景

資料為 FSC-147 官方 val 的全部 **1,286 張圖**，每張輸入一張 RGB 圖像及官方前三個示例框，由模型尋找與示例相同類型的物件。真實數量取原始點標註個數，共 **82,042 個物件**；每圖最少 7 個、最多 2,092 個，中位數 27 個，平均 63.80 個。沒有執行 test 評估，也沒有用 test 選參。

MAE 是每張圖「多數或少數了幾個」的平均絕對誤差；RMSE 先將每張誤差平方、取平均再開根號，因此對少數嚴重失誤更敏感。兩者單位都是物件數，不是百分比。

| 按每圖真實數量分組 | 圖片數 | 真實數量平均／中位數 | MAE（個） | RMSE（個） |
|---|---:|---:|---:|---:|
| 全部：7–2,092 個 | 1,286 | 63.80／27 | **9.39** | **33.26** |
| 少於 50 個 | 888 | 21.33／18 | 2.29 | 5.21 |
| 50–299 個 | 359 | 111.20／93 | 15.64 | 30.14 |
| 至少 300 個 | 39 | 594.41／458 | 113.44 | 165.85 |

整體平均有方向誤差為 −4.24 個，表示加總後偏向少數。高密度組只有 39 張，不能只看總體 MAE 就認為所有場景都可靠；後續仍需檢查漏檢、遮擋、小物件及尺度差異的具體原因。

[GeCo2 論文表 1／表 6](https://arxiv.org/html/2511.08048v1) 的 val 參考為 MAE 9.40、RMSE 33.28。本輪 9.38958／33.26304 與之接近，但不能把這點差距寫成改進：我們採精確點數作真值，上游入口採預生成密度圖的總和；CUDA／PyTorch 環境也有差異。此次沒有以不同閾值反覆選出較低分數。

## 流程與可核對證據

1. 固定上游程式版本、官方 FSC 專用模型和 SAM2 Hiera Base+ 權重。作者 Hugging Face 權重與原 Google Drive 版本的 475 個模型張量逐一核對，內容全部一致。
2. 伺服器直接下載 1,286 張 val 圖像及三份標註，1,289 個檔案逐一對照原官方資產的 SHA-256；公開模型和資料沒有繼續從本機大檔上傳。
3. 通過 CUDA 算子前向／梯度檢查、權重載入核驗、M1 單元測試，以及官方 val 順序前 20 張的 smoke。
4. 以 FP32、batch 1、TF32 關閉執行完整 val。沿用上游縮放、1024 補邊、示例尺度處理、0.11 相對閾值及 0.5 NMS；逐圖保存數量、框座標、密度總量、空間誤差和耗時。
5. 獨立程式重新計算整體及分組指標，對照所有真實點數、樣本清單和程式雜湊；全部通過。修復前已有的 342 張圖，其檢測框和計數與新結果完全一致。

首次完整評估因 `1989.jpg` 的邊緣標註 `408.00000000000006` 超出圖寬 408 而停止，屬於浮點尾差。修復只容許極小的 float64 尾差，真正越界及非有限座標仍會停止流程；原始標註沒有更動，也沒有刪點。全 val 中只有這一點屬於尾差越界；包括精確邊界，共 9 張圖、19 個點歸入最外側網格。六項單元測試在本機與伺服器均通過，失敗紀錄及部分結果保留。

## 密度圖與資源需求

M1 由每個最終檢測框建立總量為 1 的高斯分布，屬於**由檢測結果生成的密度圖**，尚未訓練密度預測分支。全部圖片的密度總量均與檢測數一致，最大數值差約 `2.27e-13`；這只證明總量守恆，不等於每個物件位置都正確。

GAME(1) 為 **11.91**，GAME(2) 為 **15.56**，分別計算 2×2 與 4×4 網格內的計數誤差之和，再對圖片平均。目前沒有其他方法在相同口徑下的 GAME 對照，不能據此宣稱空間品質較好。

| 資源／速度項目 | 實測 |
|---|---:|
| GPU | 系統回報 NVIDIA GeForce RTX 4090，49,140 MiB 顯存 |
| 完整評估主循環 | 183.98 秒，約 3 分 4 秒 |
| 平均模型推論時間／圖 | 0.130 秒 |
| 中位／第 95 百分位推論時間 | 0.097／0.292 秒 |
| PyTorch 峰值 allocated | 5,517 MiB，約 5.39 GiB |
| PyTorch 峰值 reserved | 7,512 MiB，約 7.34 GiB |

主循環時間包含圖像讀取、推論、M1 密度圖及結果寫入，不含下載、環境安裝和模型初始化。逐圖推論時間只計同步後的模型呼叫。這些是推論資源數據，不能直接當作訓練所需顯存或吞吐量。

## 後續工作

B0 已建立可核對的計數基準，M1 已通過數值守恆檢查。下一步依 Plan B 分別驗證尺度補充提示（M2）與重疊切片（M3），重點觀察高密度組，同時檢查一般圖片有沒有退步；之後才進入 M4 密度分支的訓練容量試跑。M2、M3、M4、外部資料集、定位指標和最終 test 均尚未完成。
