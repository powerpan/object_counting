# 學校 GPU 遷移與驗證

2026-11-09。計數系統從 AutoDL 移至學校 HPC4，保留原模型、M3 3×3／T2 路由和評估口徑。這次工作只確認部署可用，不新增訓練、選參或完整資料集成績。CARPK、FSC-147 和歷史負結果保持原樣。

## 執行前確認

已確認登入與 Slurm 權限，可使用 `amd` 和 `gpu-l20`。Python 3.12、CUDA 11.8、GCC 11.5 可由現有軟體環境提供，官方套件索引、GitHub 和作者權重來源可連通。空閒 GPU 數量會變動，不代表已取得分配；額度報表的期間使用量也不等於剩餘總額。

獨立建立工作目錄和 Python 環境。登入節點只負責傳送程式、提交工作和讀取狀態；安裝與編譯放在 Slurm CPU 工作，推論放在 GPU 工作。帳號、服務連線、私人路徑和工作識別碼只存私人操作記錄。

## 本次固定範圍

1. CPU 建置：8 核、32 GiB、最多 45 分鐘；PyTorch 2.7.1+cu118、Torchvision 0.22.1+cu118，編譯原版本 CUDA 注意力算子。
2. 公開權重和三張 val 圖像由學校伺服器直接下載。檔案逐一對照原凍結 SHA-256；本機只傳程式與小型來源憑據。
3. 單張 L20、4 核、32 GiB、最多 10 分鐘；執行算子前向／梯度核對與三圖部署測試。模型使用 FP32、關閉 TF32、batch 1，allocated 上限 12 GiB。
4. 圖片由既有展示例和官方 val 清單固定選出，寫入 `configs/hpc4_migration_v1.json`。逐圖核對原生輸出與查詢介面一致、B0 計數等於已存 AutoDL 結果、密度有限且總量等於計數，並實際執行凍結的最終路由。

三圖測試只能證明這些部署檢查通過，不能代表全資料集重現，亦不是新泛化成績。不讀 test 選參，不執行舊控制器；輸出另存 `results/hpc4-migration-v1`，既有輸出不覆寫。CPU 與 GPU 資源另記，不重用歷史實驗帳本。

此文件、設定與新入口先提交推送，才傳至學校和提交工作。每次執行核對來源憑據與固定上游版本。下載、編譯、雜湊、算子、計數、有限值、顯存或時限檢查失敗時保留診斷並停止，不自動重試、降低門檻或換模型。
