# M4-v2 開跑前實作核對

方案先於實測以 `6ea52ea` 提交。這份補充及程式亦先提交推送，再執行新 GPU 工作。沒有改損失、取樣、資料分割或候選門檻。

新增分支共 2,144,705 個參數，比 S 多 2,304 個，來自首層增加的一個輸入通道。最後卷積輸出仍用乘 100 的密度尺度；M1 輸入不乘 100。單次凍結前向保留 adapted／centerness，同時沿用原框提取、SAM auto 分支和最終後處理，避免另一次密度特徵前向造成不必要耗時。推論不使用真值。

為遵守第二輪「新入口先通過等價 gate」的共同規則，執行順序明確為：**32 圖起點等價及核算 → S 密集訓練圖診斷及核算 → S 記錄型融合及核算 → v2 容量試驗 → 同集 B0 留出參照及核算 → v2 seed 42 訓練及核算**。這只把技術 gate 移到診斷之前，所有設定仍在診斷前固定；不會根據診斷數值決定或修改 v2 設定。

固定分割中每輪共有 3,359 次樣本，batch 8 共 420 批。為沿用同一張圖的增強序列，增強索引取原 S 擬合清單的位置；四次重複樣本在同輪使用相同增強。留出與正式驗證沒有增強。每輪保存 396 張留出預測及檔案雜湊，獨立核算重算 RMSE、最佳輪次和第 10 輪停止判斷。

本次控制器使用新的 `results/m4-v2-v1/workflow_v1.json`，帳本為同目錄 `m4_budget_ledger_v2.json`；原 L 取消帳本保持停止狀態。新帳本導入舊累計一次，共用原 M4 鎖；失敗、中斷及核算都結算，不允許覆寫既有結果或自動重跑。每次首次執行記錄新方案／程式提交及全部來源雜湊；原五份來源保持不變。L 檢查點不在新入口讀取範圍內。

此版入口在 seed 42 訓練和核算後停於 `awaiting_validation`，或第 10 輪停止後標記 `negative_safety_stop`。前者仍需接續已登記的密度 gate、完整 val 和獨立核算，不能稱為第二輪完成；後續入口先實作、檢查與提交再執行。後者不自動啟動候選驗證、其他種子或新實驗。這項排程邊界不改動 M4-v2 評估方案。
