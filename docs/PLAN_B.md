# Plan B 實施方案

更新日期：2026-10-18。這份文件記錄實際執行版本；未完成的項目都是計畫，不代表已取得成果。

## 研究問題

在 GeCo2 的預訓練主幹保持凍結的條件下，補充未被示例涵蓋的物件尺度、處理密集小物件，並加入點標註監督的密度分支，是否能降低密集場景誤差，同時維持整體精度？

## 方法與執行次序

| 階段 | 工作 | 通過條件 |
|---|---|---|
| B0 | 環境、CUDA 算子、官方 FSC 權重及資料來源核驗；驗證集 smoke，再跑完整 val | 實際 CUDA 前向／反向成功；權重與資料可追溯；數值差異完成解釋 |
| M1 | 每個最終檢測框產生總量為 1 的高斯密度圖 | 邊界截斷後重新歸一化；密度積分與檢測數一致；原計數不變 |
| M2 | 第一輪檢測後，從未覆蓋尺度中選高相似度、高置信度框作補充示例 | 兩輪循序執行；確認無目標漂移；與等算力對照比較 |
| M3 | 由示例尺寸／預測密度觸發重疊切片 | 明確處理切片外示例、全圖座標還原和跨切片去重；不讀真值觸發 |
| M4-head | 只訓練新增密度分支，讀取高解析 query 特徵與 objectness | 有限損失與梯度；凍結參數不變；可中斷恢復；完整 train 學習曲線 |
| M4-ft | 在 head 基礎上低學習率調整末端上採樣／預測層 | 與 head 用相同資料、預算及驗證選擇規則；Hiera 仍凍結 |
| 最終確認 | 凍結方法，測試集一次評估，CARPK 外部檢查及展示 | 完整報告成功與負結果，不以測試集結果回頭選參數 |

M2 需先取得第一輪預測，不能與第一輪作為同一批並行；可另行驗證重用主幹特徵。M3 的 1536–2048 輸入方案也不能只改一個尺寸參數，上游存在 1024 的固定座標與特徵網格。

M4 預計研究約 5–10M 參數的卷積解碼器、約 30 epochs，以及區域級檢測／密度融合。這是後續設計範圍，尚不是已驗證配方。融合後報告數量須等於最終密度圖的積分；若物件位置只來自檢測，須明確說明其數量可能與融合計數不同。

## 資料與評估

FSC-147 官方 train／val／test 分別為 3,659／1,286／1,190 張，類別分別為 89／29／29 類。訓練只用 train；驗證集用於選擇與消融。B0 不讀 test 圖像或標註。官方推論程式預設遍歷 val 和 test，訓練程式也每輪評估 test，因此不直接啟動這些入口。

只採用上游 README 指向的 FSC／FSCD 專用檢查點，不用 multi-dataset demo 權重。下載後記錄 URL、大小和 SHA-256，核對權重鍵與載入差異；`strict=False` 不代表權重已正確匹配。

主要指標為 MAE、RMSE，附樣本數與真實數量分布；分組為少於 50、50–299、至少 300 個物件，另按示例相對尺寸和類別分析。區間估計分別採圖像配對與類別配對 bootstrap。空間品質採 GAME(1)、GAME(2) 和中心點定位指標，定位配對容許距離須在正式評估前固定。

消融包括 GeCo2→M1→M2→M3→M4，以及 M2、M3、M4 分別單獨加入 M1、head 對照 ft。選參與融合校準須有分組驗證記錄。最終候選及評估規則在測試前凍結；未預先指定的測試後分析只能列為探索結果。

成功條件：相對官方 GeCo2，同時降低 test RMSE、降低至少 300 個物件組的 MAE，且整體 test MAE 增幅不超過 2%。報告差異與信賴區間；不得把單次數值下降直接寫成穩定提升。

## 計算與停止條件

本輪改用 AutoDL 的單卡 48GB 實例。原提案的 A40、RunPod 費用及執行時數估計不再當作已確認條件。先記錄每圖／每步時間，再估算完整實驗成本。

先以 FP32、batch 1 完成前向／反向，再依峰值顯存與穩定性測 batch 2、4，充足時才試 8。目標使用率可提高到約 80–85%，仍保留算子工作區與密集圖波動空間；48GB 不是 batch 8 必定能跑的保證。不直接沿用舊設備的 4GB 配額。

遇到官方權重無法取得、算子無法可靠編譯、資料／權重不匹配或數值異常，先保存診斷再停止相依實驗。單次 OOM 不自動反覆重啟大批次。完成一個可核對階段後保存摘要並推送，不把仍在執行的工作標成完成。
