# 短測後的安排與備用方案

2026-11-09 首次推論前記錄。當時 FSCD-LVIS 尚未產生預測，本頁先固定接續工作與備案。我們要補足系統的適用範圍證據；換資料集並不能保證誤差下降。

執行補記：四階段已於同日18:20完成，結果及核算見[完整報告](FSCD_LVIS_EXTERNAL_RESULTS.md)。以下原定流程與備案規則保留；備案尚未執行。

## 已安排的 FSCD-LVIS 接續

四個學校作業已提交並核對依賴關係，不需要逐步重新下指令：

| 階段 | 範圍 | 資源上限 | 往下執行的條件 |
|---|---|---|---|
| 技術短測 | 固定 20 張 unseen train，B0／最終系統成對推論 | 一張 L20，15 分鐘 | 正常結束、密度與原生介面核驗通過 |
| 短測核算及時間准入 | 原始標註、保存框、密度、計數與 GAME 重核 | CPU，10 分鐘 | 核算通過；固定估時不超過 7,200 秒 |
| 完整對照 | 全部 2,242 張 unseen test、84,298 個目標 | 一張 L20，2 小時 | 不按短測精度篩選；凍結方法與清單不變 |
| 最終核算 | 全量逐圖重建、計數重算及配對區間重放 | CPU，10 分鐘 | 通過後才發布正式成績 |

前一步失敗會取消相依作業。GPU 只在推論階段配置，CPU 核算不占卡；完整作業排隊時間仍由學校決定，不能由短測拿到卡推定完整作業會立即開始。兩個推論入口有獨立時間／顯存限制，不會因排程等待而放寬。

結果發布時，同列真值分布、B0／最終 MAE、RMSE、GAME、路由、時間、顯存和配對區間。MAE、RMSE 的點估計皆下降才記為計數改善；兩個 95% 區間上界皆小於零才記為本次對照支持改善。否則按實際結果寫為不確定、部分改善或退步，不追加參數搜尋。來源、依賴與資源核對見 [排程憑據](../results/fscd-lvis-external-v1/pipeline_submission.json)。

## 第一備案：固定畫質敏感度檢查

若外部資料集沒有帶來改善，交付仍可回答「原系統能做甚麼、在哪些輸入條件下容易失效」。我們保留已完成的 FSC-147 test：1,190 圖上 MAE 7.64454 → 7.32143、RMSE 39.37197 → 34.49030；這是點估計下降，配對區間仍跨零，原完整成功標準未通過。[已核算結果](FINAL_FSC147_RESULTS.md)

畫質檢查另用開發集，不重跑舊正式 test。現在已按 `SHA256("quality-v1|" + 檔名)` 遞增固定前 128 張 val，沒有依真值數量、預測或好壞案例選圖。[清單](../manifests/fsc147_quality_backup_v1.json) 與 [設定](../configs/fsc147_quality_backup_v1.json) 已備妥。

每圖固定四個條件：原圖、解析度降至一半再還原、JPEG 品質 60、亮度乘 0.75。全部維持原輸出尺寸、示例框和點座標，共 512 個圖像條件，沿用相同權重與路由。解析度降採樣是資訊損失測試，不把它誇稱為物件幾何尺度泛化。

完整表格同時報每種條件下的絕對誤差、相對原圖的增加量，以及 B0／最終系統的配對差值；按原圖 SHA 分組抽樣，不把同圖四個版本當四份獨立樣本。保留全部四列，不能只報變好的擾動。val 已用於開發，因此這是畫質敏感度診斷，不是新的獨立泛化證明，也不改寫原 test 結論。

這個備案目前完成設計與清單固定，推論／核算入口尚待實作和提交，**尚未執行或排 GPU**。預定先 8 圖技術核驗、最多 10 分鐘；全部條件最多 1 GPU 小時、24 GiB allocated，再獨立 CPU 核算。仍先完成目前 FSCD-LVIS，不占第二張卡。

## 外部資料備選：MCAC-M1

MCAC-M1 是作者定義的 MCAC 單類別子集，包含不同物件的重複排列，具框、中心點與遮擋比例，比只換另一套停車場資料更適合檢查本專案的重複物件設定。作者頁列 test 1,013 張、19 類；它是合成影像，不能假定與真實 FSC 影像更接近或一定得分較好。[作者資料頁](https://mcac.active.vision/)

已實際確認官方 ZIP 可存取，HEAD 大小為 21,093,063,478 bytes；未下載大包、未跑模型。作者程式固定在 `1ca1f30614e0809f72dca8e225f8dd5dbe31be5d`。其 M1 測試設定為中心裁切 672、遮擋門檻 70；讀取器按 `occlusion < 70` 計數，且中心點有座標軸轉換。直接數 JSON 內所有物件會錯。程式預設還有 `drop_last: True`，我們的完整評估必須保留所有清單項，不漏掉最後一批。[測試設定](https://github.com/ActiveVisionLab/ABC123/blob/1ca1f30614e0809f72dca8e225f8dd5dbe31be5d/configs/ABC123testM1.yml)、[讀取器](https://github.com/ActiveVisionLab/ABC123/blob/1ca1f30614e0809f72dca8e225f8dd5dbe31be5d/data.py)

正式採用前，尚需核對資料使用條件、ZIP 內容與雜湊、裁切後可見目標／提示框定義及實際清單。論文和網頁的 MCAC 總分割筆數並不完全一致，1,013 是參考數字，不是我們已驗證的樣本數。若進入實測，先固定完整 M1 定義和示例選法再看預測；同樣保留 B0、全部負結果與固定配對核算。[原論文](https://arxiv.org/html/2309.04820v2)

其他候選暫不優先：PixMo-Count 的正式評估集不提供點位置，不能直接核算密度分布；CoCount 雖有三個正示例，但目前公開 test 預覽的點陣列為空，另需辨別其已修正標註版本。兩者都不是接上現有管線就能完成相同評估的替換品。[PixMo-Count 資料格式](https://huggingface.co/datasets/allenai/pixmo-count/blob/main/README.md)、[CoCount test](https://huggingface.co/datasets/BBVisual/CoCount-test)、[作者修正說明](https://github.com/bbvisual/CountEx#corrected-test-annotations)

MCAC-M1 保留為一個資料候補，畫質檢查則是較小成本的交付備案。CARPK、FSCD-LVIS 與任何後續結果會一起保留；沒有安排「換到改善為止」的連續資料集搜尋。
