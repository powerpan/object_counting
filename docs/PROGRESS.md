# 開發與實驗進度

## 2026-10-18：B0 啟動

已確認租用 GPU 對系統呈現為 NVIDIA GeForce RTX 4090，總顯存 49,140 MiB。單卡配置，25 核 CPU、92GB 主機記憶體、30GB 系統盤及 50GB 資料盤。SSH 專用金鑰登入已實測成功，憑證不存於此倉庫。

原始鏡像為 Python 3.10.8／Ubuntu 22.04，提供 CUDA 11.8 工具包。建置將使用 PyTorch 2.7.1 的 cu118 版本以配合同一工具鏈；上游安裝範例採 cu126，這項環境差異需在基線驗證中一併記錄，不宣稱逐位元一致。

已固定上游版本並檢查推論／訓練入口。發現上游預設執行 test，故本輪需獨立的 val-only 入口；不直接執行原始推論／訓練腳本。

環境安裝程序已在伺服器啟動，使用獨立 Python 環境，並保存退出狀態。尚待：安裝完成、CUDA 算子數值測試、官方 FSC 專用權重取得、資料核驗、基線 smoke、完整驗證集評估、M1 及後續模組。

目前沒有新的 MAE／RMSE 或訓練成果。

## 2026-10-18：中斷恢復與評估入口

重新登入確認服務端安裝仍存活；本機中斷的資料下載已續傳完成。官方 FSC 權重、SAM2 權重、FSC 圖像壓縮包及三份標註檔均已在本機取得並記錄 SHA-256。這不代表遠端搬移及載入驗證已完成。

已實作 val-only 評估入口，明確檢查權重鍵、沿用上游預處理和後處理、記錄逐圖計數、真值分布、GAME、時間及顯存。已完成語法檢查；尚未取得 GPU 實際推論結果。

M1 的四項 CPU 單元測試已通過，覆蓋空檢測、重疊及邊界情況下總量守恆、同總量但位置不同的 GAME 差異，以及無效框中心拒絕。這是演算法實作的測試，不能據此宣稱真實模型密度圖品質或精度提升。

目前下載／搬移速度是建置瓶頸。一般 CUDA Python 依賴改從 HTTPS 套件鏡像取得；PyTorch／Torchvision 仍固定官方 cu118 wheel。檔案傳至遠端後必須核對雜湊才使用。詳細命令與評估差異見 [執行與判讀](REPRODUCTION.md)。

已在遠端啟動有超時限制的 B0 串接流程，目前狀態為等待環境及資產。資料包經本機檢查含 1,286 張 val 圖像；沒有 test 圖像。待雜湊和各項檢查通過後，才會依序執行 smoke 與完整 val。這項排程不代表 CUDA 檢查或推論已經通過，也未開始訓練。

## 2026-10-18：改用伺服器直接下載

已停止本機的大檔上傳。FSC-147 的 1,286 張 val 圖像及三份標註由伺服器直接取得，共 1,289 個檔案，耗時 197.16 秒；全部逐檔雜湊均與原官方資產一致。第三方鏡像只提供傳輸，沒有更換資料版本或 split。

環境建置曾在 GitHub 複製階段遇到 TLS 連線提前結束。使用 AutoDL 官方學術加速後成功取得固定版原始碼，並完成環境建置：PyTorch 2.7.1+cu118、Torchvision 0.22.1+cu118、CUDA 11.8。依賴檢查通過。

自訂 deformable-attention CUDA 算子的 FP32 前向結果與 PyTorch 參考實作最大絕對差為 `4.656612873077393e-10`，雙精度梯度檢查通過。四項 M1 測試也在伺服器通過。以上證明環境與這些算子可用，不代表 GeCo2 的實際計數精度已驗證。

作者 Hugging Face 的 FSC 專用檔案已由伺服器下載完成，整檔 SHA-256 與固定版 LFS 記錄一致。與原 Google Drive 檢查點逐項比較後，475 個模型張量的形狀、float32 型別與完整內容雜湊全部一致；差異清單為空。檔案大小不同不影響這些模型參數的等價性，優化器與其他訓練狀態不屬於本次比較範圍。證據保存在 `results/b0-environment/checkpoint_equivalence.json`。

已啟用等價權重並恢復 B0 等候流程，仍需等待 SAM2 資產核驗後才進入真實圖像推論。原串接流程在安裝失敗時已停止，未越過檢查直接執行推論。之後公開資產優先由伺服器直接取得，不恢復舊的大檔上傳。
