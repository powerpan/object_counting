# S 型先驗證：執行順序修訂

2026-10-18，S42 尚在訓練、L42 尚未啟動時，依使用者要求修訂。目的是先取得 S 型的完整驗證結果，減少等待第一批正式成績的時間。

原順序是 S42 訓練 → L42 訓練 → 兩者驗證。新順序如下：

1. 保持當前 S42 程序運行，完整完成 30 輪。
2. 核對 S42 訓練紀錄及檢查點，執行 32 圖密度 gate 與獨立核算。
3. 執行 S42 的全部 1,286 張 val，再獨立核算；此時即可報告 S 型單獨的結果。
4. 技術核驗通過後開始原定 L42 訓練，接著完成相同 gate、完整 val 與核算。
5. 兩種寬度均有完整結果後，照原規則做類別兩折選擇與融合核算。

提前看到 S 的成績，不用來重選其檢查點、修改 L 的設定或改變候選門檻。S 單獨成績與後續兩折選寬度的結果分開報告。若只有成績不理想而沒有技術失敗，仍按原定設定完成 L；OOM、非有限值、來源／等價核驗失敗與預算超限，照既有規則停止相依工作。

S 單次 6 小時、L 單次 12 小時、M4 合計 30 小時均不變。前置工作只導入一次，S 全程只計一次；先做的 S 驗證與核算會在開始 L 前扣除，L 使用扣除後的餘額。後續 L、驗證、融合及失敗耗時也逐筆入帳。

交接只處理舊排程控制器，不向 S 訓練程序發送暫停或終止訊號。舊控制器狀態及來源保留，另以新控制器接管既有 S PID。新入口先提交、推送、完成 CPU 測試與來源核對，再在伺服器執行；不覆寫原始訓練程式或早期事前規則。

這是訓練期間經授權的排程修訂，不能回寫成最初登記。最終 test 的凍結與獨立人工盲標條件維持原樣。

新控制器為 `continue_round2_s_first.py`，狀態為 `workflow_s_first_v1.json`，帳本仍用 `m4_budget_ledger_v1.json`。舊 `workflow_budget_v1.json` 在保存快照後標記為已被取代，不能依它重開 L。原本等待兩個 head 完成的驗證入口不再使用。

新帳本先導入前置耗時，再把原 S 的完整耗時結算一次。各子步驟保留 10 秒供終止與結算。呼叫既有 L 訓練包裝器時，傳入的是「本次委派額度」，因此額外保存 `L_delegated_budget_s_first_v1.json`，分別列出全局剩餘與本次上限；全局總額以帳本為準，不把包裝器中的 `remaining_total_seconds` 誤當全局餘額。所有原有來源憑據保持不變，新順序另外保存第五份來源憑據。
