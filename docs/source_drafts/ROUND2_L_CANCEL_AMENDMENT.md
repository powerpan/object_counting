# 第二輪修訂：取消 M4-head-L，加入訓練集密集圖檢查

修訂日期：2026-10-18（草案；提交後以提交雜湊為準）。適用文件：`docs/ROUND2_PROTOCOL.md` 第 2.3、2.4 節及第 1 節執行次序。

**本修訂必須在查看任何 L 型輸出之前提交。** L 已產生的檢查點、損失紀錄與 train-holdout 數值一律不讀取、不評估、不作為任何結論的依據；檔案保留並記錄 SHA-256，只用於證明沒有被使用。

## 1. 決定

1. 立即停止 `head-L-seed42` 訓練。
2. 第 2.4 節的「兩種寬度以類別兩折交叉驗證選擇」改為只有 S 一個寬度；不做寬度選擇。
3. 原定的種子 43、44 重訓（針對選出的寬度）取消；種子重訓改在 M4-v2 通過候選門檻後執行（見 `M4_V2_PROTOCOL.md`）。
4. R2-2 區域融合仍以 S 依原規則執行一次，只作紀錄，不作為最終候選；最終 M4 候選改由 M4-v2 產生。
5. 新增第 3 節的訓練集密集圖檢查（R2-1b），在 M4-v2 開跑前完成。

## 2. 理由（根據已核算的 S 結果，不根據 L）

S 在完整 val 上 MAE 16.62、RMSE 83.30，均明顯差於 B0（9.39／33.26），39 張 ≥300 圖全部少計。逐圖預測顯示這不是隨機誤差，而是**計數上限**：

- 全部 1,286 張 val 中，S 的最大預測約 389，與真實數量無關。
- S ÷ 真值的中位數隨密度遞減：<50 為 1.03，300–499 為 0.79，500–999 為 0.48，≥1,000 為 0.24。
- 同一批圖上，GeCo2 檢測 ÷ 真值仍為 0.87–0.95，表示特徵中有足夠資訊，問題在密度分支的讀出。

推測原因都與寬度無關，而是 S 與 L 共用的設計：

- 計數損失為相對誤差 `|ΣD̂ − N| / N`，密集圖大量少計的代價與稀疏圖小誤差相同。
- 像素損失對所有有效像素取平均，少數密集圖的訊號被稀釋；train 中密集圖比例很低。
- 早停用的 train-holdout（8 類、202 張）只有 2 張 ≥300，無法反映密集圖表現；其 MAE 7.02 與 val 結果脫節。

S 在一般圖片上已能擬合（<50 組中位比值 1.03），沒有證據顯示 2M 參數是瓶頸。L 只改變寬度，預期會重現相同上限，卻需最多 12 GPU 小時。停止 L 並把預算轉給針對上述原因的 M4-v2，資訊價值較高。

## 3. 訓練集密集圖檢查（R2-1b，無訓練）

目的：區分 S 的密集圖少計是「連訓練圖都學不到」（擬合問題）還是「訓練圖可以、未見類別不行」（泛化問題）。檢查結果只用於解讀，**不改變 M4-v2 的任何預先設定**。

- **圖片**：FSC-147 train 全部 3,659 張中，官方點數 ≥300 的圖片（包含擬合的 81 類與 train-holdout 的 8 類，兩者分開報告）。
- **模型**：S 的正式檢查點（第 29 輪），關閉資料增強；GeCo2 與 B0 前處理相同。
- **輸出**：每圖真值、S 計數、檢測計數；依 300–499、500–999、≥1,000 分組報告 S ÷ 真值與檢測 ÷ 真值的中位數，以及 S 的最大預測值。
- **判讀規則（事前固定）**：以擬合類別中 ≥500 組的 S ÷ 真值中位數為準。
  - < 0.7：記為「擬合問題」——損失／目標設計無法讓模型輸出高密度。
  - ≥ 0.9：記為「泛化問題」——訓練圖可擬合，未見類別失敗。
  - 介於兩者：記為「混合」。
- **預算**：≤ 0.5 GPU 小時。計入 M4 合計 30 小時。

## 4. 預算帳本

報告停止 L 時的實際狀態：已完成輪數、已用秒數、M4 累計秒數與剩餘秒數。L 已用時間仍計入 M4 合計上限，不因取消而退回。

## 5. 不變的部分

除本文件列明的項目外，`ROUND2_PROTOCOL.md` 其餘規則不變，包括 M3-v2、M2-v2、類別兩折交叉驗證、候選門檻、test 前凍結清單與停止條件。M3-v2 不需訓練，可在 R2-1b 與 M4-v2 期間交錯執行。
